# WF-IoT reviewer-revision implementation map

This file documents the reproducibility changes implemented for the WF-IoT
camera-ready revision. It is not a source of experimental results.

## Reviewer 1 — computational complexity and energy

Implemented:

- analytical parameter count;
- FP32 and theoretical INT8 weight footprint;
- analytical MAC count;
- Raspberry Pi / CPU batch-1 latency benchmark;
- external power-log integration;
- system and dynamic energy per inference.

Relevant files:

- `scripts/complexity.py`
- `src/fire_transformer/complexity.py`
- `scripts/edge_benchmark.py`
- `scripts/power_benchmark_loop.py`
- `scripts/energy_from_powerlog.py`
- `docs/energy_protocol.md`

No latency, power, or energy value is considered reportable until measured on the
target hardware.

## Physical onset, coverage, and lead time

A physical onset is defined strictly by a `0 -> 1` transition of the fire annotation
within one acquisition file.

Windows ending while fire is already active are excluded from the early-warning
classification dataset.

Event identity is `(acquisition_file, onset_timestamp)`. Coverage is the fraction of
physical onsets receiving at least one correct pre-onset warning. Lead time is computed
once per covered event from the earliest correctly warning window.

Relevant files:

- `src/fire_transformer/data.py`
- `src/fire_transformer/evaluation.py`
- `tests/smoke_test.py`

## Models used in the WF-IoT experimental comparison

The experimental comparison uses:

- FT-64;
- FT-128;
- BiLSTM-BCE;
- BiLSTM-FL.

FT-32 is not part of the WF-IoT experimental evaluation in this repository.

## Statistical convention

For metric `m`, first average repeated seeds within each held-out node:

```text
m_bar[k] = mean_r m[k,r]
```

Then report:

```text
mu_macro = mean_k m_bar[k]
sigma_node = sample_std_k m_bar[k]
```

Seed-level variability is reported separately and is never pooled with
between-node variability.

## Scientific integrity rule

No estimated or provisional LONO, horizon, latency, power, or energy result may be
presented as measured evidence. Only outputs generated by the final scripts and actual
hardware measurements may be transferred to the camera-ready paper.
